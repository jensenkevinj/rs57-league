# RS57 League App — System Overview

## 1. High-level architecture

- Python project with a domain model, a pure rules engine, a nightly data sync pipeline, a local admin UI, static site generation, and validation.
- Data is stored in JSON under `data/` with strict writer ownership:
  - `data/derived/` → nightly Action only
  - `data/manual/` → local admin tool only
  - `data/history/` → frozen season importer only
- Public site output lives in `site/`, generated by nightly builds and not written by local developer runs.

## 2. Directory layout

- `rs57/`
  - core code and command entrypoints
- `rs57/admin/`
  - Flask + HTMX admin UI
  - templates and static assets
  - manual data store, reconciliation, settings, commit flow
- `data/`
  - `derived/` — ESPN-derived season data
  - `manual/` — keeper claims, overrides, payouts, season settings
  - `history/` — frozen completed seasons
- `site/` — generated public HTML
- `tests/` — unit and integration coverage
- `docs/` — rules, ESPN semantics, phase notes

## 3. Main components

### `rs57/models.py`
- Defines all JSON-loaded schemas using Pydantic
- Enforces:
  - `Money` as strict integer dollars
  - `extra="forbid"` to catch schema drift
  - no raw dicts passed around
- Key model types:
  - `Manager`, `FranchiseName`, `Season`
  - `Player`, `RosterEntry`
  - `KeeperSlot`, `KeeperClaim`
  - `SalaryOverride`
  - `PlayerOrigin`, `OriginSource`
  - prize-related models like `WeeklyHigh`, `StudAward`, `Payout`

### `rs57/keeper_rules.py`
- The pure keeper rules engine
- Computes keeper salaries and validates keeper claims
- Key rules:
  - `effective_base_salary()` uses un-reverted overrides if present
  - `keeper_salary()` adds fee + $5 tax if kept prior year
  - prospects: base only, no fee, no tax
  - `FEE_TIERS = {0:0, 1:0, 2:5, 3:15}`
  - `MAX_KEEPERS = 3`, `MAX_PROSPECTS = 1`
  - no salary cap
- Audit checks:
  - `check_base_continuity()` for the ratchet across seasons
  - `check_override_balance()` for league-wide override balance
- Prospect rules:
  - `PROSPECT_RULES_TIGHTENED = 2026`
  - rookie check is REVIEW, repeat claim is ERROR

### `rs57/espn.py`
- ESPN API client and payload mapping
- Reads:
  - league metadata
  - rosters
  - draft detail
  - matchups
  - boxscores
  - transactions
- Also handles ESPN core API for player origins
- Critical semantics:
  - `keeperValue` before draft vs `keeperValueFuture` after draft
  - `base_salary_field` is recorded in derived season data

### `rs57/sync.py`
- Syncs one season from ESPN into `data/derived/{year}.json`
- Writes derived season documents only
- Uses:
  - `EspnClient`
  - `build_season()`
  - `prior_prospect_ids()` from history
- Important design:
  - `data/derived/` is rebuildable and owned by nightly
  - salary overrides are not baked in here

### `rs57/origins.py` + `rs57/origins_sync.py`
- Manage `data/derived/player-origins.json`
- Keep player NFL career origin facts separate from derived season files
- `origins.load_player_origins()` returns exact draft/debut sources only
- `load_first_season_bounds()` includes bounds
- `origins_sync` is the only writer of `player-origins.json`
- Merge-only behavior:
  - never overwrites existing origin values
  - never removes recorded players
  - keeps unresolved players listed for retry

### `rs57/history.py`
- Writes frozen completed seasons to `data/history/`
- Strict invariant:
  - `write_season()` raises if the file already exists
- The historical store is read by validation and by prospect-history queries
- Frozen season data is immutable unless deliberately deleted and re-imported

### `rs57/admin/`
- Local Flask admin tool that writes only `data/manual/`
- Uses HTMX for live previews
- Key files:
  - `rs57/admin/__init__.py` — Flask app and routes
  - `rs57/admin/store.py` — `ManualStore` guard around `data/manual/`
  - `rs57/admin/derived.py` — read-only derived loader
  - `rs57/admin/screens.py` — builds `TeamScreen` and `SeasonScreen`
  - `rs57/admin/gitops.py` — commit/push preview and staging
  - `rs57/admin/reconcile.py` — compare recorded claims to ESPN keeper picks
  - `rs57/admin/templates/` — UI templates
- Admin pages:
  - season overview
  - team keeper entry form
  - settings
  - overrides
  - payouts
  - commit preview
- Design guarantees:
  - single writer for manual files
  - no `safe` filter in templates, autoescaping enforced
  - no arithmetic on money in templates
  - local-only binding to `127.0.0.1`
  - commit button re-checks git index

### `rs57/site.py`
- Static site generation from `data/derived/`, `data/manual/`, `data/history/`
- Writes to `site/` in CI, `.preview/` locally
- Pure rendering layer with Jinja templates
- Maps model data into public pages
- Ensures HTML output is generated, not computed in templates

### `rs57/validate.py`
- Validates all loaded `data/` content
- Checks:
  - schema and model loadability
  - cross-file references
  - recorded keeper claims against rosters
  - ratchet and override balance audits
  - origin file status and unresolved players
- Reports as:
  - `ERROR`
  - `REVIEW`
  - `SKIPPED`
- `SKIPPED` is explicit and never implied

### `rs57/stats.py`
- Pure prize rules engine
- Computes:
  - weekly high score
  - most points season award
  - positional studs
  - survivor elimination winner
  - unlucky high-loser award
  - champion/2nd/3rd payouts
- Handles tie-splitting and remainder reporting as REVIEW
- Uses exact score and lineup data, not projections

## 4. Data ownership and invariants

- `NO FILE HAS TWO WRITERS`
  - `data/derived/` → nightly sync
  - `data/manual/` → local admin only
  - `data/history/` → history importer only
- `data/manual/` reads `data/derived/` but never writes it
- `data/derived/` reads ESPN and writes itself only
- `data/history/` is write-once per season
- `player-origins.json` is separate to avoid rewriting immutable player origin facts
- All money is integer dollars; no floats for salary fields
- `SalaryOverride.reason` is free-text and must remain escaped
- Prospect eligibility is derived from external ESPN draft/debut data and treated as REVIEW when uncertain

## 5. Important domain concepts

- Keeper ratchet:
  - `RosterEntry.base_salary` = what player cost his manager this season
  - next season’s base is this season’s computed salary
  - `keeperValue` vs `keeperValueFuture` semantics are critical
- Fee tiers:
  - 0 keepers → $0
  - 1 keeper → $0
  - 2 keepers → $5 total
  - 3 keepers → $15 total
- $5 tax:
  - applied when player was kept prior year
  - waived on drop, not trade
  - prospect keeps do not set the tax flag
- Overrides:
  - represent draft-cash trades
  - `actual_salary` is authoritative while live
  - `reverted=False` means ESPN is distorted
  - live overrides should net zero league-wide
- Prospects:
  - limited to 1 per team
  - after 2026, must be rookies
  - prospect repeat claims are blocked
  - rookie check is REVIEW for unknown or external data issues
- No salary cap exists anywhere

## 6. Command-line entrypoints

- `python -m rs57.admin`
- `python -m rs57.sync --year <yr>`
- `python -m rs57.origins_sync --year <yr>`
- `python -m rs57.validate`
- `python -m rs57.site [--preview]`
- `python -m rs57.backfill` (history importer)

## 7. Development and tests

- Use `.venv` and install optional `admin` extras for Flask
- `pytest` is the test runner
- Important tests:
  - `tests/test_purity.py` ensures pure modules do not import Flask/IO
  - `tests/test_admin.py` covers admin UI behavior, no arithmetic in templates, no safe filter
  - `tests/test_models.py`, `test_espn.py`, `test_validate.py`, `test_stats.py` validate core behavior
- The repo includes hand-built fixtures:
  - `fixtures/keeper_cases.json`
  - `fixtures/prize_cases.json`
  - `fixtures/prospect_cases.json`
